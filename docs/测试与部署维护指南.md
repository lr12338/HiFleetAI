本文档是当前项目的统一运行、测试、联调、排障入口。它收敛了原先分散的测试指南与维护说明，目标是让后来者按一条清晰路径完成：

## 2. 当前推荐测试基线

最近一轮系统验证通过的可复现基线是：

- 数据库：SQLite
- 数据文件：`data/app-dev.db`
- 本地管理员账号：`admin / admin`
- 后端：`127.0.0.1:8000`
- 前端：`127.0.0.1:5173`

当前不建议把 PostgreSQL 模式作为首次联调入口，因为最近验证中它仍受环境驱动问题阻塞。

### 9.2 当前环境限制

最近一轮验证中已确认：

- 当前账号访问 Docker daemon 会返回 `permission denied`
- MinIO 未能在该环境中完成启动验证

因此，当前更稳妥的系统联调路径仍然是 SQLite 基线。

## 10. 常见问题

### 10.1 登录失败

优先检查：

- 本地管理员是否已创建
- 当前服务是否真的使用了目标 SQLite 库
- `8000` 端口是否命中了旧服务

### 10.2 前端页面能开但接口异常

优先检查：

- 后端是否真的运行在 `127.0.0.1:8000`
- `vite.config.ts` 的 proxy 是否被改动
- 是否使用了旧的浏览器缓存或旧 dev server

### 10.3 PostgreSQL 端口是开的，但应用仍起不来

如果应用报：

- `no pq wrapper available`

说明问题在 Python 驱动运行时，不在端口连通性本身。此时应先补齐：

- `psycopg-binary`
- 或系统 `libpq`

### 10.4 MinIO 无法验证

如果当前账号无法访问 Docker daemon，就无法声称本轮已完成 MinIO 启动验证。此时应在验证报告中按事实记录，而不是跳过后伪造成功。
