# 文档索引

`docs/` 用于存放 HiFleetAI 的主说明文档、阶段交付材料、验证报告、交接文档、开发日志与历史归档。

## 1. 推荐阅读顺序

如果你第一次进入项目，建议按以下顺序阅读：

1. `../README.md`
2. `项目总览与开发方案.md`
3. `系统架构说明.md`
4. `当前开发状态.md`
5. `测试与部署维护指南.md`
6. `验证报告/当前系统验证报告.md`
7. `交接文档/项目交接说明.md`
8. `../HiFleetAI开发方案.md`
9. `../Harness驱动开发规范.md`

## 2. 主文档

- `项目总览与开发方案.md`
  - 项目定位、范围、目录结构和开发方向。
- `系统架构说明.md`
  - 当前后端、前端、Harness、聊天入口与模型网关的结构说明。
- `开发规范.md`
  - 开发流程、版本与提交规则、Agent 协作约束。
- `测试与部署维护指南.md`
  - 统一的运行、测试、联调与排障入口。
- `当前开发状态.md`
  - 当前阶段、已完成能力、未完成能力和当前阻塞。

## 3. 阶段交付与验证

- `阶段交付与收口/第二阶段收口说明.md`
  - 第二阶段交付范围、验收结论与阶段风险。
- `验证报告/当前系统验证报告.md`
  - 最近一轮真实系统级验证结果与环境阻塞。

## 4. 交接文档

- `交接文档/项目交接说明.md`
  - 面向后续开发者和 Agent 的接手入口。

## 5. 管理与过程文档

- `task-board.md`
  - 当前任务状态总表。
- `开发日志/`
  - 开发过程日志、阶段日志、任务日志。

## 6. 历史归档

- `历史归档/`
  - 存放旧版计划、阶段快照、旧提示词、旧规范与 ADR。

## 7. 文档维护规则

- 主文档以当前代码状态和最新验证结果为准
- 历史文档只承担追溯职责，不再承担主说明职责
- 不把密钥、运行产物、本地数据、缓存写入文档
- 如果文档与代码冲突，以当前代码与最新验证结果为准
